# 2026-04-24 M30 Milestone Direction Selection

## 개요
M29 Reviewed-Memory Loop Refinement 완료에 따라, 차기 Milestone(M30)의 방향을 결정합니다. 주요 선택지는 선호사항의 프롬프트 주입(Option A)과 세션 간 지속성(Option B)입니다.

## 분석 및 판단
1. **루프의 완결성 (Functional Completion)**: M29를 통해 "교정 채택 → 후보 생성 → 활성화"까지의 UI/Backend 흐름이 완성되었습니다. 그러나 현재 활성화된 선호(ACTIVE preference)가 실제 모델 응답에 명시적으로 반영되고 사용자에게 그 적용 여부가 시각화되는 "프롬프트 주입(Prompt Injection)" 단계는 아직 보완이 필요합니다.
2. **사용자 가치 우선순위**: 사용자가 자신의 피드백으로 에이전트를 가르쳤을 때, 가장 즉각적인 가치는 "다음 응답이 내 선호를 따르는가"에서 옵니다. 세션 간 지속성(Option B)도 중요하지만, 단일 세션 내에서도 루프가 완벽히 동작함을 증명하는 것이 "Teachable Agent" 컨셉의 핵심입니다.
3. **CLAUDE.md 및 TASK_BACKLOG 정합성**: `CLAUDE.md`의 현재 포커스인 "reviewed-memory loop through activation plus explicit stop"을 기술적으로 완성하기 위해서는, 활성화된 선호가 실제 효과(Active Effect)를 발휘해야 합니다. `TASK_BACKLOG`에서 언급된 `[검토 메모 활성]` 프리픽스 주입 등이 이 단계의 구체적인 타깃입니다.
4. **구현 리스크 관리**: 현재 `ollama.py` 등에 기본적인 선호 전달 로직은 존재하나, 이를 모든 어댑터로 확장하고 적용 여부를 투명하게 추적/표시하는 것은 모델 응답 생성 경로의 안정화가 필요한 작업입니다.

## 결론
M30의 테마를 **"Preference Prompt Injection"**으로 결정하여, 사용자가 활성화한 선호가 실제 모델의 지능적 행동 변화로 이어지는 "Reviewed-Memory Loop"의 마지막 퍼즐을 완성할 것을 권고합니다.

## 권고 사항
- **RECOMMEND: Option A (Preference prompt injection)**
- ACTIVE 상태인 선호를 모델 호출 시 시스템 프롬프트 또는 컨텍스트에 효과적으로 주입하십시오.
- `TASK_BACKLOG`의 계획대로, 선호가 적용된 응답에 `[검토 메모 활성]`과 같은 시각적 표시를 추가하여 투명성을 확보하십시오.
- 세션 간 지속성(Option B)은 M30 이후 또는 M30의 하위 축으로 검토할 것을 권장합니다.
