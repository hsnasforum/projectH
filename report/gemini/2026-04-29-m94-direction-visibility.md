# 2026-04-29 M94 방향 제언: 선호 반영 가시성 강화 (Gemini)

## 1. 개요
M85-M93에 이르는 '신뢰도 기반 선호 메모리'의 기술적 토대(SQLite 백엔드 패리티, 프론트엔드 타입 안정성, 후보 연동)가 완결되었습니다. 현재 PR #71~#83이 발행되어 머지 대기 중인 상태에서, 다음 단계인 M94의 구현 방향을 제언합니다.

## 2. 조사 및 판단

### 2.1. 현재 상태 요약 (M85-M93)
- **백엔드:** SQLite 기반의 신뢰도 시드 및 세션 감사 요약 기능이 완성되었습니다.
- **프론트엔드:** `PreferencesPayload` 및 `PreferenceRecord` 인터페이스가 완결되었으며, 모든 타입 우회(`as`)가 제거되어 견고한 타입 시스템을 확보했습니다.
- **UI:** 선호 후보(`candidate_preferences`)가 프론트엔드 상태로 연동되어 표시될 준비가 되었습니다.

### 2.2. M94 후보군 비교
- **후보 A (자동 승격 UX):** 신뢰도 높은 후보를 자동으로 선호로 승격시키는 흐름은 효율적이나, 사용자가 '왜' 승격되었는지 체감하기 어렵다면 신뢰를 잃을 위험이 있습니다.
- **후보 B (영향 가시성 강화):** 현재 '선호 N건 반영' 배지는 있으나, 구체적으로 어떤 문구와 로직이 응답에 영향을 주었는지에 대한 'Source Marking'이 부족합니다. 이는 시스템의 투명성과 사용자 교육(teachable) 측면에서 가장 높은 가치를 제공합니다.
- **후보 C (머지 후 시작):** 기술적 부채 관리 측면에서는 유리하나, 제품적 진전(slice)을 정의하기에는 정적인 선택입니다.

## 3. 권고 (Recommendation)

**RECOMMEND: implement Option B — preference 활성화 후 실제 응답 영향 가시성 강화**

### 기술/제품적 이유:
1. **투명성 확보:** 사용자가 작성한 선호나 시스템이 추천한 후보가 실제 응답을 어떻게 개선했는지 시각적으로 증명함으로써, 메모리 기능의 효용을 직접 체감하게 합니다.
2. **품질 축(Quality Axis) 강화:** Milestone 3의 핵심 가치인 'Grounded' 응답의 연장선상에서, 선호 메모리 역시 근거(Source)를 명확히 함으로써 모델의 할루시네이션을 억제하고 통제력을 높입니다.
3. **데이터 기반:** M85-M93에서 정교화된 `candidate_preferences`와 `applied_preferences` 데이터를 사용자 인터페이스에서 가장 효과적으로 소비하는 다음 단계입니다.
