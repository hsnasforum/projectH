# 2026-04-30 M112 Review Queue UX 강화 다음 단계 권고

## 상황 요약
- M110 (검색 필터) 및 M111 (항목 수 헤더) 완료로 Review Queue의 기본 가시성이 확보됨.
- 현재 stacked draft PR 체인(#91–#104)이 운영자 승인 대기 중이며, Review Queue UX 강화 아크가 진행 중임.
- 다음 단계 후보로 액션 UI 인라인화(A), 배지 추가(B), 통계 요약(C), 아크 전환(D)이 제시됨.

## 판단 근거
- **사용자 가치 우선**: M110/M111을 통해 "어떤 항목이 있는가"는 알 수 있게 되었으나, "어떤 항목을 먼저 처리해야 하는가"에 대한 맥락(Context) 정보가 여전히 부족함.
- **후보 비교**:
    - **A (액션 UI 인라인)**: 현재 코드상 이미 항목별 버튼이 존재하나, 항목 카드가 길어질 경우 가독성이 떨어질 수 있음. 다만, 이는 가시성 확보보다는 편의성 개선에 가까움.
    - **B (배지)**: 항목의 "신선도(Age)", "우선순위(Priority)", "출처 유형(Source Type)" 정보를 제공하여 사용자의 의사결정 비용을 직접적으로 낮춤. 이는 `GEMINI.md`의 "same-family user-visible improvement" 및 "quality axis" 기준에 부합함.
    - **C (통계 요약)**: 헤더 수준의 정보로 유용하지만, 개별 항목 처리 효율에는 B가 더 직접적인 영향을 미침.

## 권고 사항
`RECOMMEND: implement B) Review Queue 배지 (Age, Priority, Source Type)`
- **이유**: M110 검색과 M111 카운트로 항목 탐색은 가능해졌으나, 각 항목의 중요도나 시급성을 판단할 근거가 UI에 노출되지 않고 있음. 배지를 통해 맥락 정보를 인라인으로 제공하는 것이 다음 가장 큰 UX 마찰(의사결정 지연)을 해결하는 길임.

## Axis 1 수준 Scope 제안
- `ReviewQueuePanel.tsx`에서 각 항목에 `created_at` 기반의 상대 시간 배지(예: "방금", "1시간 전") 추가.
- `promotion_basis` 또는 `item_type`을 기반으로 한 출처 유형 배지 추가.
- 고품질(`is_high_quality`) 배지 외에 강조가 필요한 우선순위 항목에 대한 시각적 구분 적용.
