# 2026-04-30 M113 Review Queue UX 강화 다음 단계 권고

## 상황 요약
- M110(검색), M111(카운트), M112(배지)를 통해 Review Queue의 가시성과 맥락 정보 제공 기능이 크게 개선됨.
- 현재 Review Queue의 가장 큰 UX 페인 포인트는 액션 버튼(수락/거절/보류)의 위치임.
- 현재 코드 구조상 액션 버튼들이 각 항목 카드의 최하단에 위치하고 있어, 문장(statement)이 길거나 대화 맥락/증거 상세 내용이 노출될 경우 사용자가 액션을 취하기 위해 카드를 끝까지 스크롤해야 하는 불편함이 있음.

## 판단 근거
- **UX 완성도**: M110~M112가 "판단을 돕는 정보"를 강화했다면, M113은 "판단 결과를 제출하는 행위" 자체를 효율화하는 단계임.
- **Action-First 접근**: 사용자가 배지와 요약 정보만으로 즉시 판단이 가능한 경우(예: 고품질 항목), 스크롤 없이 즉시 액션을 취할 수 있도록 하는 것이 생산성 향상에 직결됨.
- **후보 비교**:
    - **A (액션 UI 인라인)**: 스크롤 문제를 직접 해결하며 Review Queue UX 아크의 완성도를 찍는 핵심 기능임.
    - **B (통계 요약)**: 유용한 정보이나, 개별 항목 처리의 물리적 불편함을 해결해주지는 못함.
    - **C (아크 종료)**: 현재 UX 마찰이 명확하므로, 이를 해결하고 아크를 닫는 것이 논리적임.

## 권고 사항
`RECOMMEND: implement A) Review Queue 액션 UI inline`
- **이유**: 정보 탐색(Search)과 식별(Badge) 기능이 갖춰진 현재, 액션 버튼을 스캔 지점(카드 상단/우측)에 가깝게 배치하여 스크롤 없이 즉시 처리가 가능하게 하는 것이 가장 시급한 UX 개선임.

## Axis 1 수준 Scope 제안
- `ReviewQueuePanel.tsx`에서 각 항목의 액션 버튼 블록을 카드 상단부(문장 우측 또는 배지 영역 옆)로 이동하거나, 헤더 섹션에 콤팩트하게 배치.
- 버튼 디자인을 아이콘 중심 또는 콤팩트한 칩 형태로 변경하여 시각적 노이즈를 줄이면서 접근성 강화.
- 상세 정보(맥락, 증거, 사유 입력란)는 기존처럼 하단에 유지하여, 판단이 더 필요한 경우에만 스크롤하도록 설계.
