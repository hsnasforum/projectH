# Gemini Code Review: pipeline-launcher.py

**날짜:** 2026-05-21
**대상:** `pipeline-launcher.py` (TUI Launcher)
**분석자:** Gemini CLI (Advisory Owner)

## 1. 개요
클로드가 런타임(`supervisor.py`, `cli.py`)의 버그를 식별한 것에 이어, 본 보고서에서는 사용자 접점인 `pipeline-launcher.py` 자체의 구조적 결함과 UX 위험 요소를 분석합니다.

## 2. 주요 분석 결과 및 문제점 (L1–L10)

### L1. 동기식 실행으로 인한 UI 프리징 (Blocking UI)
- **현상:** `pipeline_stop`, `pipeline_restart` 호출 시 내부적으로 `subprocess.run`과 `time.sleep` 루프가 실행되어 UI 스레드를 점유함.
- **위험:** 명령 완료(최대 20초+)까지 런처가 응답하지 않음. 사용자는 프로그램이 멈춘 것으로 판단하여 강제 종료를 시도할 수 있음.

### L2. Subprocess 예외 처리 누락
- **현상:** `_run_runtime_cli`에서 `timeout` 발생 시 `subprocess.TimeoutExpired`가 발생하나 이를 처리하는 로직이 없음.
- **위험:** 런타임 제어 명령 지연 시 런처가 크래시(Crash)되며 종료됨.

### L3. CJK(한글) 문자 폭 계산 오류
- **현상:** `_fit_text`에서 `len()` 함수를 사용하여 레이아웃 폭을 계산함.
- **위험:** 한글은 터미널에서 2컬럼을 차지하므로 `len()` 기반 계산 시 UI 레이아웃이 우측으로 밀리거나 깨짐. 특히 에이전트 이름이나 로그 메시지에 한글이 섞일 때 심각함.

### L4. 터미널 리사이즈(Resize) 미대응
- **현상:** `curses.KEY_RESIZE` 이벤트 처리가 루프 내에 명시되어 있지 않음.
- **위험:** 사용자가 창 크기를 조절할 때 화면이 즉시 갱신되지 않거나 이전 레이아웃의 잔상이 남음.

### L5. 하드코딩된 레인 인덱스
- **현상:** `focused_agent` 및 키 바인딩(1, 2, 3)이 3개 레인으로 고정되어 있음.
- **위험:** 레인 설정이 변경된 프로젝트에서 유연하게 대응하지 못함.

## 4. 권고 조치
1. **Async 전환:** `pipeline_stop` 등의 작업을 스레드 혹은 비동기 루프로 분리하여 UI 응답성을 유지하십시오.
2. **Width 라이브러리 도입:** 한글 출력을 위해 `wcwidth` 등 터미널 폭 계산 라이브러리 사용을 권장합니다.
3. **방어 코드 강화:** 하위 프로세스 실행 시 모든 예상 가능한 예외(`TimeoutExpired`, `PermissionError` 등)를 포착하여 UI 메시지로 변환하십시오.
