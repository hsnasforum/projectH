## 변경 이유
- `CONTROL_SEQ 1316` implement handoff가 Codex lane에 전달된 뒤 빠르게 `TASK_DONE`으로 닫혔지만, 요청된 dist/E2E 산출물과 `/work` closeout이 없어 작업이 멈춘 상태였다.
- 같은 상황에서 runtime health가 한동안 `ok/continue`로 남아 operator가 멈춤을 정상 진행으로 오해할 수 있었다.

## 핵심 변경
- 프론트엔드 production dist를 `npx vite build`로 재생성해 `is_highly_reliable` promote 결과 표시가 `app/static/dist/assets/index.js`에 반영된 상태를 확정했다.
- `promote correction pattern with high recurrence shows highly reliable feedback` Playwright 시나리오를 추가해 반복 교정 승격 결과에 `신뢰도 높음` feedback이 표시되는지 확인한다.
- `derive_automation_health()`가 active implement handoff 아래에서 `IMPLEMENT_ACTIVE + READY/prompt_visible`가 오래 지속되면 `implement_active_idle` attention으로, `implement_idle_timeout` 뒤 same handoff retry 대기 상태는 `idle_release_pending` recovering으로 표시하도록 했다.
- 새 automation health 분기 단위 테스트를 추가했다.
- `.pipeline/README.md`에 implement idle 상태가 `ok/continue`로 숨겨지지 않아야 한다는 no-silent-stall 계약을 문서화했다.
