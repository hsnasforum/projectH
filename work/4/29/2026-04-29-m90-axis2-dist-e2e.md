## 변경 이유

- M90 Axis 1의 `PreferencePanel.tsx` 변경이 production dist에 아직 반영되지 않아 `app/static/dist/assets/index.js` 재빌드가 필요했다.
- handoff가 요구한 preference 관련 E2E 격리 실행에서 기존 `preference-not-applied-btn` 시나리오가 그룹 실행 중 badge DOM 교체 타이밍으로 실패했다.

## 핵심 변경

- `app/frontend`의 실제 repo 빌드 방식인 `npx vite build`로 `app/static/dist/assets/index.js`를 재생성했다.
- `dist` 결과물에 `candidate_preferences` / `candidatePreferences` 기반 candidate count 연결이 반영됨을 확인했다.
- `e2e/tests/web-smoke.spec.mjs`의 `preference-not-applied-btn` 시나리오에서 초기 `demo-session` 로드 완료와 `/api/chat/stream` 응답 완료를 기다린 뒤 최신 `main` badge와 popover 내부 버튼을 대상으로 클릭하도록 안정화했다.
- React 컴포넌트 추가 수정은 하지 않았다. M90 Axis 1의 `PreferencePanel.tsx` 변경은 handoff가 지정한 기반 변경으로 포함되어 있다.

## 남은 리스크

- `app/frontend/package.json`에는 여전히 `build` script가 없다. 이번 라운드는 handoff의 dist 재빌드 목적을 기존 문서와 이전 라운드에서 사용한 `npx vite build`로 충족했으며, package script 추가는 범위 밖이라 수행하지 않았다.
- 이번 E2E 수정은 기존 flaky 시나리오의 대기와 selector 안정화에 한정했다. 전체 `make e2e-test`는 handoff 범위와 리스크 기준상 실행하지 않았다.
- 브랜치 생성은 로컬 `.git/refs` 쓰기 제한 때문에 실패했다. 커밋, push, PR 생성은 수행하지 않았다.
