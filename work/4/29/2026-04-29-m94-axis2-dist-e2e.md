## 변경 이유

- M94 Axis 1에서 `MessageBubble` applied preferences 팝오버에 `신뢰도 높음` 배지를 추가했으므로, production dist를 재빌드하고 관련 E2E 신호를 확인해야 했다.
- `applied-preferences` 별도 실행 명령은 현재 테스트 제목과 매칭되지 않아 `No tests found`가 발생했다. 실제 popover 시나리오를 별도 grep으로 실행하니 누적 로컬 선호 fixture 상태에 의존해 실패했다.

## 핵심 변경

- `cd app/frontend && npx vite build`로 `app/static/dist/assets/index.js`를 재빌드했다.
- 재빌드된 dist에서 `신뢰도 높음`, `is_highly_reliable`, `isHighlyReliable` 문자열이 반영된 것을 확인했다.
- `reviewed-memory loop: badge 클릭 시 popover가 열리고 선호를 일시중지할 수 있습니다` E2E에 `/api/chat/stream` deterministic route를 추가했다.
- 해당 route는 첫 응답에는 `applied_preferences`를 포함하고, popover에서 pause 후 두 번째 응답에는 `applied_preferences`를 생략해 pause 효과 확인을 누적 preference 상태와 분리했다.
- handoff 경계에 따라 source React 추가 수정, docs 변경, `.pipeline` control 변경, 커밋/push/PR 작업은 하지 않았다.

## 남은 리스크

- 전체 Playwright smoke, `make e2e-test`, 전체 unit test는 실행하지 않았다. 이번 handoff가 dist 재빌드와 관련 preference/popover E2E 격리에 한정되어 좁은 검증만 수행했다.
- `-g "applied-preferences"` 명령은 현재 테스트 제목과 맞지 않는다. 후속 verify/handoff에서 해당 grep 명령을 유지할지, 실제 test title grep으로 바꿀지 판단해야 한다.
- 로컬 `.git/refs` 쓰기 제한 때문에 요청된 브랜치 생성은 실패했다. 커밋, push, PR 생성은 수행하지 않았다.
