## 변경 이유

- M118 Axis 1에서 `/api/preferences`가 top-level `injected_count`를 노출했지만, frontend 타입과 `PreferencePanel` 표시, dist 산출물, 브라우저 smoke가 아직 연결되지 않았습니다.
- handoff가 요구한 `npm run build` 경로가 `app/frontend/package.json`에 없어 같은 dist 빌드가 반복해서 실패할 수 있었습니다.

## 핵심 변경

- `PreferenceRecord`에 optional top-level `injected_count` 타입을 추가했습니다.
- `PreferencePanel`에서 `injected_count > 0`인 선호에만 `data-testid="preference-injected-count"` 배지를 표시하고, `applied_count > 0`이면 `N회 주입 (R% 적용)` 형식으로 전환율을 함께 표시합니다.
- `app/frontend/package.json`에 `build: vite build` 스크립트를 추가해 handoff의 `npm run build` 명령이 실제 Vite dist 재빌드를 수행하도록 했습니다.
- `app/static/dist/assets/index.js`와 `index.css`를 재생성했습니다.
- `e2e/tests/web-smoke.spec.mjs`에 `preference injected count badge appears for injected preferences` 시나리오를 추가해 positive count 표시와 zero count 숨김을 검증했습니다.
- smoke inventory count를 128로 맞추고 README / PRODUCT_SPEC / ACCEPTANCE_CRITERIA / MILESTONES / NEXT_STEPS / TASK_BACKLOG를 최소 범위로 동기화했습니다.
